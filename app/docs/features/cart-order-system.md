# Cart & Order System (E-Commerce Flow)

**Status:** Implemented (Sprints 1–4, merged to develop 2026-03-28)
**Replaces:** Legacy 3-step rental flow (`/wypozyczalnia/*`)

---

## Overview

A full e-commerce cart → checkout → Przelewy24 payment flow for item rental services.
Customers add rental items to a DB-backed cart, proceed to checkout, and pay online.
Admins manage orders in the Filament panel.

---

## Architecture

### DB Schema (6 tables)

| Table | Purpose |
|-------|---------|
| `carts` | Per-user, per-org shopping cart (`active` / `abandoned` / `converted`) |
| `cart_items` | Cart line items with `start_date`, `end_date`, `quantity`, price snapshot |
| `orders` | Placed orders — customer data, totals, P24 fields, `expires_at` TTL |
| `order_items` | Immutable snapshot of items at order time |
| `payments` | P24 payment records with webhook payload |
| `order_status_history` | Auto-generated by state machine |

### Inventory Source

`OrderItem` (not `Rental`) is the authoritative inventory source.
`RentalAvailabilityService::getAvailableQuantity()` queries `order_items JOIN orders`
with fallback to legacy `rentals` table (Sprint 2 coexistence; `rentals` fallback can be
removed once all legacy records are exhausted).

### Order State Machine (`OrderStatusStateMachine`)

```
pending_payment → paid → confirmed → in_progress → completed
                ↓                ↘
            cancelled (terminal)  refunded (terminal)
```

- `pending_payment` has `expires_at` TTL (20 min) — expired orders are cleaned up by scheduled job
- Inventory is blocked by: `paid`, `confirmed`, `in_progress`, and non-expired `pending_payment`

- `resources/views/checkout/return.blade.php` — payment result (5 states: success/pending/failed/cancelled/unknown)
- `resources/views/orders/index.blade.php` — paginated order list with status badges

- `app/Filament/Resources/OrderResource.php` — order management (`$module = 'rentals'`)

- `app/Filament/Resources/OrderResource/Pages/ListOrders.php`
- `app/Filament/Resources/OrderResource/Pages/ViewOrder.php`
- `app/Filament/Resources/OrderResource/RelationManagers/OrderItemsRelationManager.php`

### Scheduled Jobs
- `app/Console/Commands/CleanupExpiredOrders.php` — cancels `pending_payment` orders past `expires_at`

- `app/Console/Commands/CleanupAbandonedCarts.php` — deletes `abandoned` carts older than 7 days
  - Schedule: daily at 02:00, `->withoutOverlapping()->onOneServer()`

## Przelewy24 Integration

Package: `mnastalski/przelewy24-php` ^1.6 (PHP 8.3 compat, REST v3)

Config: `config/przelewy24.php`
```env
P24_MERCHANT_ID=
P24_REPORTS_KEY=
P24_CRC=
P24_LIVE=false
```

CSRF exclusion in `bootstrap/app.php`:
```php
$middleware->validateCsrfTokens(except: ['/webhooks/przelewy24']);
```

Webhook flow: P24 POSTs → `Przelewy24Service::handleWebhook()` → verifies signature → verifies transaction → `order->status()->transitionTo('paid')`.

## Security

- Cart and order items scoped to both `user_id` AND `organization_id` (IDOR prevention)
- `CartItemOwnershipException` → 403 (not 500)
- Checkout submit exceptions logged server-side, generic error shown to user
- Webhook: signature verification before processing
- No raw exception messages exposed to users
