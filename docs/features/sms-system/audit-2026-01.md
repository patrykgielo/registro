## Critical Issues

### ~~ISSUE #0: Wrong Column Names in SMS Jobs~~ ✅ FIXED

**Severity:** CRITICAL (System breaking)
**Status:** ✅ FIXED (2026-01-25)

**Problem:**
`SendReminderSmsJob` and `SendFollowUpSmsJob` used non-existent columns:
- `customer_phone` → should be `phone`
- `customer_name` → should be `first_name` + `last_name`

**Root cause:**
```php
// WRONG - columns don't exist in Appointment model!
->whereNotNull('customer_phone')
$appointment->customer_phone
$appointment->customer_name
```

**Impact:** All scheduled SMS reminders would fail with SQL error.

**Fix applied:**
```php
// CORRECT - using actual Appointment model columns
->whereNotNull('phone')
$appointment->phone
trim($appointment->first_name.' '.$appointment->last_name)
```

**Files fixed:**
- `app/Jobs/Sms/SendReminderSmsJob.php`
- `app/Jobs/Sms/SendFollowUpSmsJob.php`

### ~~ISSUE #1: No SMS on Appointment Creation~~ ✅ FIXED

**Severity:** HIGH
**Status:** ✅ FIXED (2026-01-25)

**Problem:**
- SMS listeners existed but used wrong template keys
- `booking_confirmation` → should be `appointment-created`
- `admin_confirmation` → should be `appointment-confirmed`
- Phone was fetched from `customer->phone` instead of `appointment->phone`

**Fix applied:**
1. Fixed template keys to match database templates
2. Fixed phone number retrieval (appointment.phone with fallback)
3. Added SMS listeners for `appointment-cancelled` and `appointment-rescheduled`
4. Improved customer name handling (first_name + last_name)

**Files fixed:**
- `app/Providers/AppServiceProvider.php`

**SMS now sent on events:**
- `AppointmentCreated` → `appointment-created` template
- `AppointmentConfirmed` → `appointment-confirmed` template
- `AppointmentCancelled` → `appointment-cancelled` template
- `AppointmentRescheduled` → `appointment-rescheduled` template

### ISSUE #2: Race Condition in Spending Limits

**Severity:** MEDIUM

**Current behavior:**
```php
// SmsService::checkSpendingLimits()
$todayCount = SmsSend::whereDate('created_at', today())->count();  // Query 1
$monthCount = SmsSend::whereYear()->whereMonth()->count();          // Query 2

// ... time passes ...

if ($todayCount >= $dailyLimit) throw new SpendingLimitException();
// ← Another job could have incremented count between query and check!
```

**Impact:**
- Concurrent jobs can exceed limits
- 300+ queries per SMS send (performance)

**Fix:**
```php
// Use atomic counter (Redis)
$dailyCount = Redis::incr("sms:daily:{$today}");
if ($dailyCount > $dailyLimit) {
    Redis::decr("sms:daily:{$today}");
    throw new SpendingLimitException();
}
```

### ~~ISSUE #4: Webhook Verification Bypass~~ ✅ FIXED

**Severity:** MEDIUM (Security)
**Status:** ✅ FIXED (2026-01-25)

**Problem:** Webhooks accepted without verification if `SMSAPI_WEBHOOK_SECRET` not set.

**Fix applied:** Multi-layer security verification:
1. **HMAC signature** - if `SMSAPI_WEBHOOK_SECRET` is configured
2. **IP whitelist fallback** - if no secret but IP is from known SMSAPI ranges
3. **Production REJECT** - if neither signature nor IP whitelist passes
4. **Development ALLOW** - only in non-production with warning log

**IP whitelist ranges:**
- `195.201.229.*`, `195.201.230.*`, `195.201.231.*` (EU)
- `78.133.254.*`, `78.133.255.*` (PL)

**Files modified:**
- `app/Http/Controllers/Api/SmsApiWebhookController.php`

### ISSUE #7: No Retry for Failed SMS

**Severity:** MEDIUM

**Current behavior:**
- Failed SMS marked in DB but no automatic retry
- Next job run (1 hour later) doesn't retry failed SMS

**Impact:** Important transactional SMS may not reach customer.

**Fix:** Add `RetryFailedSmsJob` or exponential backoff in `SendReminderSmsJob`.
