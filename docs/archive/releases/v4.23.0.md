# Release v4.23.0

**Data:** 2026-01-27
**Branch:** `release/v4.23.0`
**Status:** W przygotowaniu

---

## Podsumowanie

Zunifikowany system przypomnien (reminders) z konfiguracją w panelu admina, naprawa podwójnego wysyłania emaili, hardening produkcyjnego Docker i CI/CD seeders.

---

## Features (Nowe funkcjonalności)

### Unified Reminder System (#155)
- Nowy `TemplateKey` enum jako single source of truth dla kluczy szablonów SMS/Email
- Model `ReminderConfig` z konfiguracją przypomnien w panelu admina (Filament Resource)
- Model `ReminderLog` z idempotentnym logowaniem wysyłek (message_key hash)
- Zunifikowany `ProcessRemindersJob` zastępujący 6 legacy jobs
- Usunięto 10 legacy plików (3 eventy, 4 joby, 3 notyfikacje)
- Usunięto 6 boolean kolumn z tabeli appointments (zastapione reminder_logs)
- 3 nowe migracje: `reminder_configs`, `reminder_logs`, `drop_legacy_flags`
- `ReminderConfigSeeder` z 6 domyślnymi konfiguracjami (3 typy x 2 kanały)

### Configurable App Name
- Nazwa aplikacji konfigurowalna w System Settings (zakładka General)
- `SettingsManager::appName()` pobiera z DB z fallback na `APP_NAME`
- Wszystkie szablony email/SMS używają dynamicznej nazwy

### Horizon Dashboard Authorization (#163)
- Env-based authorization: non-production = dowolny zalogowany user, production = whitelisted emails
- `HorizonServiceProvider` z gate opartym na `APP_ENV`

### Production Docker Hardening (#169)
- Scheduler: 18 brakujących zmiennych env (CACHE, QUEUE, MAIL, SMSAPI, GOOGLE_MAPS, LOG)
- Redis: AOF persistence, 256mb maxmemory, allkeys-lru eviction
- Horizon: healthcheck (`horizon:status | grep running`)
- App: `APP_DEBUG=false`, health-based `depends_on`
- MySQL/Redis: `start_period` na healthcheckach

### CI/CD Seeders (#169)
- Staging: dodano `ReminderConfigSeeder` do pipeline deploy
- Production: dodano 4 seeders (Roles, EmailTemplate, SmsTemplate, ReminderConfig) po migracjach

## Fixes (Naprawy)

### Double-Email Bug (#167)
- **Problem:** 6 notyfikacji wysylalo 2 emaile na raz — `toMail()` wywolywalo `EmailService::sendFromTemplate()` (email #1) i zwracalo `MailMessage` ktory Laravel `MailChannel` wyslal jako email #2
- **Rozwiazanie:** Nowy `EmailServiceChannel` zastapil `MailChannel`, metoda `toEmailService()` bez return
- **Dotyczy:** AppointmentCreated, Cancelled, Rescheduled, UserRegistered, PasswordReset, AdminCreatedUser

### SmsApiGateway Crash (#157)
- **Problem:** `$senderName` variable scope — zmienna niezainicjalizowana przed try block
- **Rozwiazanie:** Inicjalizacja `$senderName` przed blokiem try

### Mailpit Crash Loop (#161)
- **Problem:** `MP_UI_AUTH_FILE` wskazywal na nieistniejacy plik
- **Rozwiazanie:** Usunieto `MP_UI_AUTH_FILE`, publiczny Web UI na porcie 8025

### Missing SMSAPI Env Vars (#157)
- **Problem:** Kontenery Docker nie mialy zmiennych SMSAPI_TOKEN, SMSAPI_SERVICE
- **Rozwiazanie:** Dodano do docker-compose.staging.yml i docker-compose.prod.yml
